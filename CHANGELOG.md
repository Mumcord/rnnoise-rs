# Changelog

All notable changes to this project are documented here. The format is based
on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Optional, loadable model weights** (issue #3). New Cargo features:
  `embedded-model` (the default, the float blob), `embedded-model-int8` (the committed
  pre-quantized blob, ~3.0 MiB instead of 11.3 MiB) and `model-loader` (no blob embedded).
  "None" is the default turned off: `default-features = false`.
- `RnnModel::from_file(path)` and `RnnModel::from_file_with_checksum(path, expected_crc)`
  (`model-loader`), `RnnModel::to_bytes()`, and `rnnoise::crc32(&[u8])` for callers that pin a
  downloaded blob. `from_bytes` takes any `&[u8]`, so an existing memory mapping needs no extra
  API: `RnnModel::from_bytes(&mmap)`.
- The `RNNS` integrity container: `magic + format version + record count + CRC32 of the record
  stream`, in front of the unchanged `"DNNw"` records, so upstream blobs still load. The record
  header's `version` field, which used to be read and ignored, is now checked, as is each array's
  record type. New `ModelError` variants: `BadType`, `UnsupportedVersion`,
  `ChecksumMismatch { expected, actual }`, `RecordCountMismatch`, `NoEmbeddedModel`, `Io`.
- `DenoiseState::try_new()` — the constructor that exists in every feature configuration: with
  an embedded model it behaves like `new()`, without one it reports `ModelError::NoEmbeddedModel`
  instead of assuming a default model.
- `models/rnnoise_default_int8.bin` (3,179,088 B), generated by the crate itself
  (`examples/gen_int8_blob.rs` → `RnnModel::from_bytes(float).quantized().to_bytes()`); the
  feature embeds it only when `embedded-model-int8` is on. `tests/model_artifacts.rs` asserts the
  committed file is byte-for-byte what the writer produces, that loading it produces the same
  model as quantizing at runtime, and pins both blobs' checksums. Tests that need the artifacts
  skip when they are absent.
- `tests/api_surface.rs` names the new public items (`to_bytes`, `from_file`,
  `from_file_with_checksum`, `crc32`, `try_new`) in every feature combination.
- `make features` runs the feature matrix (`no-default-features`, `model-loader`,
  `embedded-model-int8`, `embedded-model-int8,model-loader`); it is part of `make check` and of CI.
- `doc/models.md`: feature semantics (including feature unification and the precedence rule),
  measured binary size and RSS per combination, and the container format.
- `Weights::Q8` carries a per-output-row `128 · Σ w` correction table, computed in
  `LinearLayer::quantize`. Only the AVX-512 VNNI tier reads it — it is what lets that tier's hot
  loop be one load plus one `vpdpbusd` per chunk instead of a load plus a `vpaddb` plus a
  `vpdpbusd`. Internal (`Weights` is not public), so no public API change.

### Changed

- **The pitch feature is computed in double, as the C reference computes it**
  (`src/denoise.rs`, `src/legacy.rs`). Upstream writes `features[2*NB_BANDS] =
  .01*(pitch_index-300)` with `.01` a `double`, so the product is computed in double and
  narrowed to float; the port used an `f32` literal, which was the one feature where it
  disagreed with the pinned pure-C oracle. Measured on `test_data/testing.raw`: 3 differing
  samples (1 LSB, `2.003e-10`) before, **0** after — the port is bit-exact against the pinned
  recipe on all four clips, and `tests/parity.rs` now asserts equality instead of a spread.
  Behaviour change: an input whose pitch index lands on the last bit can now come out 1 LSB
  apart from before. `src/legacy.rs` applies the same promotion; its measured numbers do not
  move there, because that path quantizes the GRU input to int8 anyway.
  Goldens regenerated from the pinned recipe (`WRITE_GOLDENS=1 ./scripts/c_reference.sh`); the
  golden the earlier clang build produced is kept as
  `test_data/goldens/testing.c-clang.raw` for provenance and stays within the 1-LSB
  compiler hedge.

- `default = ["embedded-model"]`: the crate now has a default feature, so an application that
  previously used `default-features = false` and `RnnModel::default()` / `DenoiseState::new()`
  must load a model instead — that is the point of the change, but it is a break for that
  configuration and the constructors are feature-gated (`impl Default` for both types, and
  `new()`).
- `src/weights.rs` is now a module directory (`mod.rs` re-exports only): `blob` (record parsing),
  `manifest` (container + checksum), `error`, `model`, `embedded`, `loader`, `write`. This is
  rule 1 of the styleguide (module roots re-export) applied to a file that had grown into a
  catch-all.
- `RnnModel` derives `PartialEq` (and `LinearLayer`/`Weights` gained it), so a round trip through
  `to_bytes`/`from_bytes` can be asserted as equality rather than as a comment.
- `rnnoise_create` with a NULL `model` returns NULL when no model is embedded, instead of
  assuming one exists.
- `rnnoise-demo` and the `process` bench now declare
  `required-features = ["embedded-model"]` (they need a model they are not handed).

- **x86-64 int8 tier v4 (AVX-512 VNNI)** — the `+128` that `vpdpbusd` needs is paid once per layer
  instead of once per chunk, and the model's hot width (384 bytes = exactly 6 chunks) keeps the
  biased activations in registers for the whole row loop with four independent accumulator chains.
  Measured per row on a Zen 4 core (Ryzen 7 7800X3D), same binary, same data: 4.88 ns with the bias
  in the loop, 4.77 hoisted to a buffer, **3.06** hoisted into registers with four accumulators;
  end to end on that box 52.8 µs → 45.5 µs of network per frame. Exact integer arithmetic
  throughout, so tier v4 stays bit-identical to `simd::scalar` (issue #16).
- The tier gate in CI now accepts both `/proc/cpuinfo` spellings for the AVX512BW flag
  (`avx512_bw` and `avx512bw`); a Zen 4 runner prints the second, so the coverage job
  reported a false negative on hardware that can actually exercise tier v4 (issue #16).

- **Style ruleset**: the adopted subset of the Google Rust style guide is now
  `doc/styleguide.md` (derivation and measured gaps:
  `doc/styleguide-adoption-plan.md`). Each rule is either tool-enforced or
  explicitly waived. `make style` — part of `make check` and of CI — checks what
  no lint can express: the stable toolchain, module-root purity, the unsafe
  islands, `SAFETY:` justifications, glob-import exemptions, one-module-per-`use`,
  `rustfmt::skip`, and the no-async/no-threads/no-`catch_unwind` rule.
- `Cargo.toml` gained a `[lints]` section (`unsafe_code`, `missing_docs`,
  `unstable_features`, `unwrap_used`, `panic`, `must_use_candidate`,
  `exhaustive_enums`, `exhaustive_structs`, `wildcard_imports`,
  `disallowed_methods`), and `clippy.toml` disallows `catch_unwind` and
  `std::thread::spawn`. `rustfmt.toml` gained `hex_literal_case = Lower`
  (`format_macro_matchers` and `imports_granularity` are nightly-only, so the
  one-module-per-`use` rule is checked by `make style` instead).
- The crate-wide `#![forbid(unsafe_code)]` claim in `AGENTS.md`/`CONTRIBUTING.md`
  was not true in practice (SIMD intrinsics and the C ABI). It is now the honest
  version: `unsafe_code = "deny"` at the crate root, with `#[allow(unsafe_code)]`
  only on the declared islands, and a `SAFETY:` justification per block or file.
- No `unwrap()` left in `src/`: pattern matching where the input proves the case,
  `expect("context")` otherwise.
- The model-geometry constants moved out of the crate root into the leaf `params`
  module; `lib.rs` only declares submodules and re-exports. `rnnoise::FRAME_SIZE`
  and the other sizes are re-exported from the crate root, so the paths are stable.
- `src/fft/plan.rs` → `src/fft/kiss_fft.rs`, named after its primary item
  (`KissFft`). Internal only: `KissFft` was never reachable from outside the
  private `fft` module, so no public path changed.
- `tests/api_surface.rs` names every exported item, so a public rename or removal
  is a compile failure rather than a silent break.
- **Real-time contract** (`doc/realtime.md`, issue #4): the frame path no longer holds
  lazy state. `DenoiseState` and `DenoiseStateV1` resolve the shared tables at
  construction and store them as `&'static`, so `process_frame` performs no lazy lookup
  at all, and the legacy path no longer clones `Arc<RnnModelV1>` per frame (an atomic
  refcount bump inside an audio callback). No numerical change.
- `benches/process.rs` reports the **distribution** per frame (mean, p50, p99, p99.9,
  max) and the headroom against the 10 ms frame budget, not only the mean, and measures
  cold start separately. `make check` and CI now also run `make rt-gate`.

### Deprecated

- `DenoiseState::with_model` and `DenoiseStateV1::with_model` are deprecated in
  favour of `DenoiseState::new_with_model()` and `DenoiseStateV1::new_with_model()`:
  `with_foo()` is reserved for
  closure accessors, so constructors take the `new_with_foo()` form. The aliases
  are source-compatible and will be removed in 0.3.

### Breaking

- `ModelError` is now `#[non_exhaustive]` (guide rule), which means downstream
  exhaustive `match` statements without a wildcard arm no longer compile. This is
  the price of being able to add error variants later without a breaking change.


### Added

- `rnnoise::warmup()` — resolve the runtime CPU feature detection before the first frame
  (`src/simd/warmup.rs`), and call it from `DenoiseState::new_with_model` /
  `DenoiseStateV1::new_with_model`. Measured: the first `is_x86_feature_detected!` call
  costs 7.1 µs, every later call 0.3 ns; moving it to construction is what makes the
  steady-state frame path free of any first-use lazy initialisation. It cannot change
  output: every tier is bit-identical to the portable reference.
- Real-time gates (issue #4): `tests/real_time_no_alloc.rs` (counting `GlobalAlloc`, 0
  allocations over the measured window — the optimiser can remove an unused allocation, so
  it is paired with the source gate), `tests/real_time_denormals.rs` (no subnormal output on
  the test signal), and `scripts/realtime_gate.py` (`make rt-gate`, part of `make check` and
  CI): no allocation, lock, lazy static, I/O, logging or CPUID probe inside a per-frame
  function, and no feature detection outside the dispatch layer.
- `doc/realtime.md`: the contract, what is enforced, the measured percentiles, and the
  denormal boundary.
- Repository scaffolding aligned with the sibling `lovelace-labs/*-rs` repos:
  `rust-toolchain.toml`, `rustfmt.toml`, `Makefile`, `VERSION`, `AUTHORS`,
  `.editorconfig`, `.gitattributes`, `.gitconfig`, `.gitmodules`,
  `.dockerignore`, `cspell.json`, `codemeta.json`, `CITATION.cff`,
  `LICENSE`, `SECURITY.md`, `CONTRIBUTING.md`, and `AGENTS.md`.
- `.github/workflows/ci.yml` aligned with the org-wide CI template.
- `src/simd/`: the int8 dot-product kernels, split per architecture (`scalar`,
  `aarch64`, `x86_64`) behind one runtime-detected `dispatch`.
- `src/fft/` split into `plan` (factors, twiddles, per-stage twiddle views),
  `scalar` (the portable reference butterflies), `x86_64` (the vector tier),
  `dispatch` and `tests`; the module root only re-exports.
- Tier-equality tests: every float and int8 kernel is asserted bit-identical to its
  portable reference (`simd/tests.rs`, `fft/tests.rs`, `common/tests`, and
  `weights/tests` for the dense-equivalence of a complete ascending index).
- CI gate for the SIMD tiers, since a skipped tier is not coverage: each run prints the
  runner's ISA flags and the tiers it exercised, and the `simd-tier-coverage` job runs the
  tier-equality tests on a real AVX-512 + VNNI machine when one is wired up through the
  repository variable `avx512_runner`, failing if a tier is skipped. What is provable without
  the hardware (tier v4's `128 · Σ q_x` bias identity) is asserted unconditionally, on every
  runner.

- CI (issue #5): the job matrix now covers ubuntu x86-64, ubuntu-arm aarch64,
  macOS (Apple Silicon) and Windows, in debug and release; `cargo deny` is part of
  the gate (`deny.toml`, `make deny`, and `make check`).
- `scripts/c_reference.sh`: builds the pinned upstream RNNoise in the scalar (`_c`)
  path in CI and runs the clip set, so the committed goldens are checked against a
  fresh oracle build instead of being taken on trust. `tests/c_reference_parity.rs`
  does the comparison with the `doc/parity.md` tolerance and skips gracefully when
  the oracle or the clips are absent.
- `test_data/clips/` (deterministic, regenerable with `scripts/make_clips.py`): a
  stable-pitch clip, a near-silence clip and digital silence, with goldens in
  `test_data/goldens/`. With the oracle built on `vec.h`'s pure-C branch (the path this
  crate ports; `-U__SSE2__ -U__AVX__` on x86-64, `-DDISABLE_NEON` on AArch64) all three
  are **bit-exact** against the pinned C reference, and `test_data/ref_out.raw` is
  reproducible within 4 samples — the previous recipe only disabled NEON, so a fresh x86
  build took `vec_avx.h` and disagreed by ~1800 1-LSB samples. Goldens regenerated from
  the corrected oracle; the assertion in `tests/c_reference_parity.rs` is now
  `max ≤ 1 LSB` for oracle-vs-golden.
- `.gitattributes` marks `test_data/**` and `*.raw` as binary: a line-ending conversion
  there changes a sample, which is what the parity harness measures.
- `src/simd/tier.rs`: the tier decision is one function (`resolve`) instead of a
  ladder duplicated per kernel, plus a `cfg(test)`-only `RNNOISE_SIMD_TIER` override
  so CI can force each path on hardware that has it — a production build pays nothing
  for it and no tier can be forced onto a CPU without the ISA. No public API changed.
- `src/simd/coverage.rs`: runs the whole pipeline once per tier the runner reports
  (float and int8 paths) and asserts bit-identical output against the scalar run,
  printing which tiers ran and which were skipped.
- `benches/process.rs` is a criterion harness (one group per implementation, active
  and silent inputs); CI saves a baseline and uploads the JSON results per runner.
- `scripts/style.sh` (`make style`, part of `make check`): the review rules that can be
  checked mechanically — module-root purity, unsafe island membership, the `SAFETY:`
  justification per file, one-module-per-`use`, glob imports only in the exemptions,
  `rustfmt::skip` only with a cited exemption, and no async/threads/`unwrap` in `src/`.
  Running it found a real gap: `src/fft/tests.rs` had unsafe calls with no `SAFETY:`
  justification (added).
- `make spell` + CI spell check with a repo dictionary in `cspell.json` (the DSP/ISA
  vocabulary: `sgemv`, `xcorr`, `pmaddwd`, `vpdpbusd`, `cepstral`, `biquad`, …).
- `simd-tier-override`: an opt-in, dev/CI-only feature that honours `RNNOISE_SIMD_TIER` in
  a normal build, so `cargo bench` can measure one kernel path against another on the same
  machine. Never enabled by default; zero cost when off.
- `Cargo.lock` is committed, so `cargo deny` checks a reproducible graph instead of
  freshly resolved versions.
- `simd::coverage` now fails instead of skipping when CI requests a tier the runner does
  not have — the promise was coverage, so an uncovered path is a failure. The
  `simd` matrix lists only tiers its runners can execute; v4 still needs an AVX-512 machine,
  and the pure-Rust identity test in `simd::tests` validates it anywhere else.

### Fixed

- `simd::x86_64::vnni::dense_q8` subtracted the `128 · Σ q_x` correction over the whole
  activation vector instead of over the length a row covers (`min(m, qx.len())`), so tier v4
  disagreed with the portable reference for any layer narrower than `qx` — the CI failure on
  AVX-512 runners through the tail-width assertion in `simd/tests.rs` (widths 7, 33, 65).
  Exact for every width again; the loads are bounded by the shorter of the two slices (as
  the reference's `zip` is), and the bias identity is asserted per row length so it is
  checkable without AVX-512 hardware.

### Performance

- x86-64 gets real int8 dot kernels, one per ISA tier (`SSE2` sign-mask +
  `pmaddwd`, `SSE4.1`/`pmovsxbw`, `AVX2`, and `AVX-512 VNNI` `vpdpbusd`), chosen
  at **runtime** from CPUID — no `-C target-cpu` needed. On an AMD Zen 3 core the
  quantized model's neural net drops from ≈487 µs to ≈84 µs per frame (5.8×), so
  the int8 path is finally *faster* than the float path on x86 instead of slower
  (full frame 519 → 119 µs, ≈84× real time); legacy 40.2 → 38.1 µs. Tier ladder
  measured on that core: 1.3 / 3.5 / 6.5 / 15.3 MACs per cycle (v1–v3).
- `simd::sparse_sgemv8x4` (the GRU matrices, ~90 % of the float network) keeps the
  eight-row accumulator in a register for the whole row group instead of
  load/store per block, accumulating per column in upstream `vec.h` order —
  bit-identical to the portable reference (float NN 289 → 248 µs/frame).
- x86-64 gets runtime-detected **float** tiers, one per ISA level, each keeping the
  reference accumulation order (one accumulator per output, or per lag, in `j` order)
  so they are bit-identical to `simd::scalar`:
  - `simd/x86_64/dense.rs` — 8 outputs per accumulator instead of the SSE2 baseline's 4
    (384×1152 layer: 33.2 → 23.5 µs/frame on a Zen 3 core).
  - `simd/x86_64/xcorr.rs` — the pitch cross-correlation, 4 (SSE2) or 8 (AVX2) lags in
    parallel (7.2 → 3.0 µs/frame in the coarse pitch search).
  - `fft/x86_64.rs` — vector butterflies with per-stage contiguous twiddle views; the
    plan now builds those views so the arithmetic stays the same per element
    (4.86 → 2.5 µs per transform, three transforms per frame).
- A sparse weight index that is **complete and ascending** — every row group lists all
  its column blocks in order, which is the case for the shipped model's GRU matrices —
  accumulates each output in ascending input order, i.e. exactly `dense_sgemv`'s order.
  Such layers are now loaded in dense row-major form at parse time (same bytes, same
  bits), which lets the float network use the wider GEMV tier. Indices that are
  genuinely sparse or out of order still run through the sparse kernel. Measured on a
  Zen 3 core: float NN 239 → 192 µs/frame.
- `Common` precomputes the triangular band weights `j / band_size` with the same f32
  division the runtime used to do, removing ~317 float divisions per band pass.
- `simd::dense_sgemv_blocks`: a dense float layer whose outputs form complete groups of
  eight is stored in a **block-major** permutation of the same values
  (`w[(o/8)*8*m + j*8 + o%8]`), so the AVX2 tier keeps four group accumulators in registers
  for the whole `j` walk instead of loading and storing them once per block — four
  independent add chains in flight, one 32-byte weight load per eight MACs. Every output
  still sums in ascending `j`, so the bits are unchanged (`simd/tests.rs` asserts
  tier == reference, and `rnnoise-demo` output on `test_data/testing.raw` is byte-for-byte
  identical). On a Zen 3 core: 384×1152 20.7 → 15.3 µs per call, conv2 12.5 → 6.6,
  conv1 2.2 → 0.8, dense_out 5.0 → 1.4; full frame 213.5 → 157.4 µs (63.5× real time),
  neural net 192.0 → 135.7 µs.

End to end on an AMD Zen 3 core (plain `cargo bench`, tier v3 selected at runtime, best
of runs): float full frame **270.6 → 208–216 µs** (≈1.3×, 46–48× real time), its DSP
front-end **31.6 → 21.8 µs**; int8 full frame **116.8 → 102–107 µs** (94–98× real
time); legacy **38.1 → 33.8 µs**. Parity is unchanged: 3 samples of 47 520 differ by
1 LSB, relative energy `2.003e-10`.

### Changes

- `rust-version` raised to **1.89** so the AVX-512 VNNI tier is unconditional
  (it is still only *used* when CPUID reports `avx512f` + `avx512vnni`; nothing
  forces AVX-512 codegen elsewhere in the crate).
- `chunks_exact(2|4)` sites rewritten as `as_chunks::<N>()` so the crate is clean
  under the lint set of the current toolchain.
- All kernels compute the same exact `i32` value, so quantized output is
  unchanged (`rel_energy 4.8e-6`); `src/simd/tests.rs` asserts SIMD == scalar and
  skips when the feature is not present.
