# Models & weights

`rnnoise-rs` ships two models and can load custom ones. This document covers what
is bundled, which feature combination embeds what, the on-disk weight format, how
to load your own weights, and the optional int8 and legacy paths.

## What's bundled

| File | Used by | Size | Format |
|---|---|--:|---|
| [`models/rnnoise_default.bin`](../models/rnnoise_default.bin) | `embedded-model` (the default) | 11.3 MiB | `"DNNw"` blob, float weights |
| [`models/rnnoise_default_int8.bin`](../models/rnnoise_default_int8.bin) | `embedded-model-int8` | 3.0 MiB | `"DNNw"` records in the `RNNS` container, int8 weights |
| [`models/rnnoise_legacy.rnn`](../models/rnnoise_legacy.rnn) | `legacy-model` feature | 87 KB | old-RNNoise `i8` layer stream |

Each blob is embedded with `include_bytes!` **only when its feature is on**, so an
application that turns the default features off carries code only and loads a blob
at startup (see [Loading weights on demand](#loading-weights-on-demand)). The
int8 artifact is generated by the crate itself: `cargo run --release --example
_gen_int8_blob models/rnnoise_default.bin models/rnnoise_default_int8.bin` writes it,
and `tests/model_artifacts.rs` asserts that the committed file is byte-for-byte what
`RnnModel::from_bytes(float).quantized().to_bytes()` produces.

> **crates.io note:** the default blob (11.3 MiB) exceeds the default crates.io
> 10 MB crate-size limit, so a crate published with `embedded-model` needs the limit
> raised. `embedded-model-int8` (3.0 MiB) fits. If a published crate excludes `models/`
> from the package, the embedding features cannot work for its consumers.

## Feature flags

| Feature | What it does |
|---|---|
| `embedded-model` (default) | embeds the float blob; the bit-exact path |
| `embedded-model-int8` | embeds the pre-quantized blob instead (~3.0 MiB) |
| `model-loader` | adds `RnnModel::from_file` / `from_file_with_checksum`; embeds nothing |

Cargo cannot express "none" as a feature, so the none case is the default turned off:

```toml
rnnoise-rs = { version = "0.1", default-features = false, features = ["model-loader"] }
```

Two consequences worth knowing:

- **Feature unification.** If any crate in the dependency graph enables
  `embedded-model`, the whole build embeds it. An application that wants the small
  binary must make sure nobody else enables the feature — which is why there is no
  `no-embedded` feature: a negative feature has no consistent answer when two crates
  in one graph disagree.
- **Precedence.** If both embedding features are enabled (unification can do this
  without anyone asking), `RnnModel::default()` uses the float blob. Without any
  embedding feature, `DenoiseState::new()` does not exist and `DenoiseState::try_new()`
  reports `ModelError::NoEmbeddedModel`; the only constructor is `new_with_model()` with
  a model you loaded yourself.
- **The artifacts are build-time inputs.** An embedding feature `include_bytes!`s its
  blob, so a checkout without `models/` fails to *build* with that feature on — that is
  deliberate (a build error is not a silent runtime one), and it is why the runtime tests
  that read the blobs skip when they are absent instead of failing.

## Feature combinations & measured size

Measured on x86-64, `--release` with `lto = true`, for a consumer binary that links
the crate, builds a `DenoiseState` and processes one frame (so the blob is really
referenced). RSS is `VmRSS` after the first frame, in a fresh process.

| Features | consumer binary | RSS after first frame |
|---|--:|--:|
| `embedded-model` (default) | 12,384,024 B | 29.3 MB |
| `embedded-model-int8` | 3,672,744 B | 9.3 MB |
| `model-loader` only (no blob) | 361,456 B | 0 until a blob is loaded |
| no features | 361,472 B | — |

A consumer that links the crate but never constructs a denoiser is **363,096 B** even
with `embedded-model` on: rustc never emits the blob if nothing references it, so the
forced cost is paid by the code path that actually denoises, not by every link. The
costs that are paid regardless:

| Artifact | with `embedded-model` | without any blob |
|---|--:|--:|
| `librnnoise.a` (staticlib — always carries the object) | 47,606,746 B | 23,803,938 B |
| `librnnoise.so` with `capi` (the C ABI references the model) | 12,442,304 B | 548,024 B |

So for a C consumer linking the static library the blob is unavoidable when the
feature is on, and for a Rust consumer it is unavoidable only on the path that builds
a state. Startup cost for the on-demand path (float blob): ~4.5 ms to read the file,
~10 ms to parse, peak RSS ~52.8 MB during loading against ~29.3 MB steady state —
the loader copies the records into owned arrays, so a mapping saves the transient copy
but not the parsed model. The int8 blob loads in ~13 ms for ~3 MB of weight storage.

## The current model

The default model is the official Xiph RNNoise model (checksum-verified against
`model_version`, and pinned by CRC32 in [tests/model_artifacts.rs](../tests/model_artifacts.rs)).
Architecture and exact dimensions are in
[architecture.md](architecture.md#the-neural-network-in-detail). The bundled blob
is a **float-only slim** version: the upstream model ships both int8 and float
weights for the quantizable layers, and the C reference uses the float ones, so
embedding just the float arrays reproduces the reference exactly while keeping the
blob smaller. The arrays present (29 of them):

```
conv1_weights_float, conv1_bias
conv2_weights_float, conv2_bias
gru{1,2,3}_input_weights_float, _input_weights_idx, _input_bias
gru{1,2,3}_recurrent_weights_float, _recurrent_weights_idx,
          _recurrent_weights_diag, _recurrent_bias
dense_out_weights_float, dense_out_bias
vad_dense_weights_float, vad_dense_bias
```

The GRU matrices use a sparse 8×4-block layout indexed by the `*_weights_idx`
arrays. In the regular model every block is present (it is dense), but the loader
and GEMV honour the block/index structure regardless, so the sparse "little"
model would also load.

## The `"DNNw"` blob format

This is upstream RNNoise's own "machine-endian" weight format (produced by
`dump_weights_blob` / `write_weights.c`), which `RnnModel::from_bytes` parses —
so a blob exported from upstream loads directly, and vice-versa.

A blob is a sequence of records, each:

```
┌──────────────────────────── 64-byte header (WeightHead) ───────────────────────────┐
│ char head[4] = "DNNw"                                                                │
│ i32  version  = 0                                                                    │
│ i32  type     (0 = float, 1 = int32, 2 = qweight, 3 = int8)                          │
│ i32  size     (payload bytes)                                                        │
│ i32  block_size = ceil(size / 64) * 64   (payload padded to 64-byte alignment)      │
│ char name[44] (NUL-terminated)                                                       │
└─────────────────────────────────────────────────────────────────────────────────────┘
  payload[size]  followed by (block_size - size) zero pad bytes
```

All integers are little-endian (the practical meaning of upstream's "machine
endian"). `rnnoise-rs` reads little-endian; big-endian hosts are not currently
supported (see [Future work](#future-work)). Float arrays are raw `f32`; index
arrays are raw `i32`.

The loader ([`weights::blob::parse_records`](../src/weights/blob.rs)) walks the
records into a name→array map, then [`weights::blob::linear`](../src/weights/blob.rs)
wires the named arrays into the ten `LinearLayer`s, validating every length (dense
layers `nb_inputs*nb_outputs`, sparse layers `32 * total_blocks` from the index
structure, biases/diag/scale `nb_outputs`) and every record type.

### The `RNNS` integrity container

A bare record stream can only be checked **structurally**: names, sizes, types. A
truncated download, a wrong model, or a blob from a newer format can be structurally
plausible and still load — and then the denoiser simply sounds worse, which is the
kind of failure an application cannot debug in the field. So the loader accepts an
optional header in front of the unchanged record stream:

```text
magic              4 bytes  "RNNS"
format version     4 bytes  u32 (1) — an unknown version is rejected, not guessed
record count       4 bytes  u32 — cross-checked against what was actually parsed
record checksum    4 bytes  u32 — CRC32 (IEEE, reflected) of the record stream only
record stream      n bytes  the unchanged "DNNw" records
```

Both shapes are accepted, so upstream exports keep loading. What is checked, and with
which error:

| condition | `ModelError` |
|---|---|
| truncated / bad record header | `Malformed` |
| record `version != 0` | `UnsupportedVersion` |
| container `format version != 1` | `UnsupportedVersion` |
| payload does not hash to the header | `ChecksumMismatch { expected, actual }` |
| record count disagrees with the header | `RecordCountMismatch { expected, found }` |
| array missing / wrong size / wrong type | `MissingArray` / `BadSize` / `BadType` |
| file unreadable | `Io` |

CRC32 is a corruption check, not an authenticity check. For a model downloaded on
demand, pin the checksum in the application and compare it before parsing:
`RnnModel::from_file_with_checksum(path, expected_crc)` (the pinned value is the CRC32
of the record stream, which is the same number for a bare blob and a container), or
`rnnoise::crc32(&bytes)` for a blob you already have in memory. The committed artifacts
are pinned in [`tests/model_artifacts.rs`](../tests/model_artifacts.rs):

| artifact | CRC32 of the record stream |
|---|---|
| `models/rnnoise_default.bin` | `0x191693b7` |
| `models/rnnoise_default_int8.bin` | `0x4e5c4930` |

### Generating the default blob

The bundled `models/rnnoise_default.bin` was generated from the official model's
C source with [`scripts/gen_blob.c`](../scripts/gen_blob.c): it `#include`s the
upstream `rnnoise_data.c`, then writes the subset of float arrays the float
compute path needs, in the `"DNNw"` record format. To reproduce, build it against
an extracted upstream model tree and run it (the script lists the exact arrays).

## Loading a custom model

```rust
use std::sync::Arc;
use rnnoise::{DenoiseState, RnnModel};

let blob = std::fs::read("weights_blob.bin")?;     // upstream "DNNw" export
let model = Arc::new(RnnModel::from_bytes(&blob)?);
let mut st = DenoiseState::new_with_model(model);
# Ok::<(), Box<dyn std::error::Error>>(())
```

With the `model-loader` feature there is a file form of the same thing, and a pinned
checksum for downloads:

```rust
use std::path::Path;
use rnnoise::RnnModel;

let model = RnnModel::from_file(Path::new("models/custom.bin"))?;
let pinned = RnnModel::from_file_with_checksum(Path::new("models/custom.bin"), 0x4e5c_4930)?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

`from_bytes` takes any `&[u8]`, so an existing memory mapping works with no extra API
and no dependency: `RnnModel::from_bytes(&mmap)` (with `memmap2`, or any mapping the
application owns). A mapping only reduces the transient copy — the parsed model is
owned — so it pays for peak RSS and for sharing pages between processes, not for the
resident model.

`RnnModel::to_bytes()` is the mirror of `from_bytes`: whatever this crate writes, it
reads back unchanged (asserted in the tests), which is how the committed int8 artifact
is kept honest.

The model's layer dimensions are fixed by this port (they match the shipped
architecture); a blob with different dimensions will fail validation with
`ModelError::BadSize`. To run a differently-shaped model you'd adjust the
dimensions in `weights::RnnModel::from_bytes`.

## int8 quantized model

`RnnModel::quantized()` converts conv2 and the GRU matrices to int8 (conv1 and the
output heads stay float, mirroring upstream's choice):

```rust
use std::sync::Arc;
let model = Arc::new(rnnoise::RnnModel::default().quantized());
let mut st = rnnoise::DenoiseState::new_with_model(model);
```

- **Layout:** each quantized layer becomes a transposed, dense `[output][input]`
  int8 matrix plus a per-output `f32` scale. The scale folds in both the weight
  scale (`max|w|/127`) and the activation scale (`1/127`), so inference is
  `out[o] = scale[o] · (q_w[o] · q_x)` with an int32 dot product.
- **Runtime:** activations (all `tanh`/`sigmoid`/GRU outputs in `[-1, 1]`) are
  quantized to int8, and each output is computed with a NEON `sdot` 4-MACs-per-
  lane dot product (inline asm; the `vdotq_s32` intrinsic is still nightly-only),
  with a portable scalar fallback that gives the identical integer result.
- **Footprint:** ~11.5 MB → ~2.9 MB of weights.
- **Stored form:** the committed `models/rnnoise_default_int8.bin` is this layout
  written by `RnnModel::to_bytes()` — int8 records plus a per-output scale, no index
  arrays, because the shipped model is dense. Loading it is a memcpy of the weights;
  `tests/model_artifacts.rs` asserts it produces the same model (and the same output,
  bit for bit) as quantizing the float blob at runtime.
- **Speed:** ~3× faster than the float path on Apple Silicon (the NN itself ~4×).
  See [performance.md](performance.md).
- **Accuracy:** not bit-exact — `rel. energy 4.8e-6` vs the float model on the
  test signal (audibly identical). That's why it's opt-in and the float model is
  the default.

Why int8 and not f16/float-stored? On this workload it's *instruction*-bound, not
bandwidth-bound; `sdot` cuts the instruction count ~4×. A naive int8 path
(dequantize to f32 in the loop) is actually *slower*; storing f32 weights is
slower still (4× cache traffic). See [performance.md](performance.md).

## Legacy (2018) model

The `legacy-model` feature bundles the original RNNoise model (the one
`nnnoiseless` uses) and exposes it as `DenoiseStateV1` / `RnnModelV1`.

- **Format:** a flat stream of `i8` layer records (`nnnoiseless`'s format):
  for each layer `nb_inputs, nb_neurons, activation`, then the weights and bias.
  Layers in order: input-dense, vad-gru, noise-gru, denoise-gru, denoise-output,
  vad-output. Activations: `0=tanh, 1=sigmoid, 2=relu`.
- **`RnnModelV1::from_bytes(&[u8])`** loads this format (validating the layer
  wiring); the bundled `models/rnnoise_legacy.rnn` is the default.
- **Speed:** *faster than nnnoiseless* — it uses `realfft` (rustfft) for the FFT,
  4-wide pitch kernels, and `sdot` int8 GRU input matmuls. See
  [performance.md](performance.md).
- **Quality:** lower than the current model (it's the old, smaller network).

## Future work

- Big-endian support in the blob loader (currently little-endian only).
- x86 VNNI kernel for the int8 path (the scalar fallback already runs everywhere).
